# Node-only consumers

The existing shared validation, release and container-release workflows support a Node-only capability without a Python application project or uv.lock. Declare no [python] capability; use validation.checks = [], [node] directory/version/checks, and release.semantic_release = true with tag_merged_commit = true. Formatting is a supported Node check alongside lint/typecheck/test/build. Metadata-only pyproject.toml may contain the same [tool.semantic_release] policy used by other consumers; do not add a [project] or Python dependency groups merely for publication.

The central release engine remains python-semantic-release 10.6.2 with the existing dependency commit parser, authorization, exact-main identity and retry/finalization behavior. Node-only jobs skip consumer uv setup/sync/lock and install the shared engine from scripts/requirements-release.txt using pip --no-deps --require-hashes. Every tool requirement is pinned with hashes; no dependency resolver runs for the Node application. Python is the control-tool runtime, not an application dependency. Existing Python/mixed consumers keep their own locked uv environment unchanged. Regenerate the shared tool export from this repository's existing uv.lock using uv export --frozen --only-group dev --no-emit-project --no-header --no-annotate; review dependency changes with the workflow revision.

Node-only releases tag the reviewed main commit and do not rewrite version files or create a version commit. Package.json remains source metadata; the GitHub release tag, OCI revision/version labels and digest identify the artifact. Metadata-only semantic configuration rejects version_toml/version_variables. A print-tag calculation uses the same engine and parser without credentials, commits, tags or registry operations. Never run publication on a working or development branch.

For containers, the existing coordinated/single-image pipelines retain candidate provenance, immutable digest, protected-main authorization and publication ordering. Node-only candidates must supply HEALTHCHECK and pass it by exact digest in a read-only, capability-free container before release tag/GitHub Release finalization. The consumer Dockerfile owns its Node production build; the shared Node validator separately runs declared checks. The pipeline does not publish an npm package.

The regression fixture in tests/fixtures/node-only has release policy metadata and Node files but no consumer uv.lock, Python project or dependencies. Tests execute its Node build, calculate v0.1.0 with the real central engine without mutation, and assert Node paths skip consumer Python dependency operations. Existing Python publication/recovery regressions remain required. Control-plane Wood installation for readiness/routing remains separate from application dependency installation.
